The problem

In a hybrid rocket, a liquid or gaseous oxidizer flows through a port cut into a solid fuel grain. The fuel surface burns back as the motor fires, so the port grows and changes shape, and thrust changes with it.

For simple circular ports this can be worked out by hand. For complex port shapes like stars, crosses, and multi-lobe designs that increase burning surface area, the geometry quickly becomes impractical to track analytically.

The approach

Instead of solving the geometry by hand, fuelgrainsim works directly from the designer's CAD drawing. It converts the cross-section into a polygon and numerically offsets the burning surface outward at each time step, clipping it against the grain's outer wall.

That means any port shape that can be drawn can be simulated, and design iterations are as fast as editing a sketch.

How it works

The pipeline runs from a DXF file to a finished set of results with no manual steps in between.

01 · Import

DXF to SVG

Each DXF in the input folder is converted to SVG through the Inkscape command line.

02 · Scale

Parse geometry

svgpathtools separates the port outline, outer wall, and a 10 mm scale bar, then scales the drawing to true dimensions.

03 · Discretize

Build a polygon

Arcs are approximated as line segments, sorted end to end, centered, and turned into a Shapely polygon.

04 · Regress

Burn back the surface

At each step the regression rate is computed and the port polygon is buffered outward by that distance.

05 · Clip

Respect the wall

The grown port is intersected with the circular case boundary so burnout at the wall is captured.

06 · Output

CSV, plots, animation

Thrust, regression rate, change in area, and perimeter are saved to CSV, plotted, and animated. Multiple grains run in parallel.

The physics

Fuel regression follows the Marxman model, where the burn rate depends on oxidizer mass flux through the port. As the port opens up, flux drops and regression slows.

Regression rateṙ = a · (ṁox / Aport)n

The fuel mass flow is the volume of grain burned in each time step. Thrust comes from the total propellant flow and the specific impulse.

Fuel mass flowṁf = ΔA · L · ρ / Δt
ThrustF = (ṁox + ṁf) · Isp · g₀

Key engineering decisions

  • Polygon buffering over analytical geometry. Shapely's buffer operation handles arbitrary shapes, including merging lobes, without special-case code.
  • Scale bar calibration. A required 10 mm reference line in the drawing guarantees correct real-world dimensions regardless of DXF export units.
  • Arc linearization. Curves are converted into short line segments at a set density, trading a small geometric error for much faster polygon operations.
  • Boundary intersection. Clipping against the case wall models the loss of burning surface once the flame front reaches the outer diameter.
  • Batch processing. A multiprocessing pool simulates a whole folder of candidate grain designs at once for quick comparison.

Example results

Output for the included four-point test grain. Hover or tap the chart to read values at each time step.

Reading the curves

  • Regressive start. Regression rate is highest at ignition, when the port is smallest and oxidizer flux is highest, then falls steadily as the port grows.
  • Near-flat plateau. The growing burning perimeter mostly offsets the slowing regression, so thrust stays within about 5% between 0.1 and 4.8 s.
  • Tail-off at the wall. Around 4.9 s the lobes reach the case wall. Burning surface is lost and thrust drops by roughly 10%.

Usage

Install from GitHub, install Inkscape for DXF conversion, then point the tool at a folder of grain drawings.

# install
pip install git+https://github.com/zsiller/fuelgrainsim.git

# run the included example
fuelgrainsim --input test_files --output results \
  --isp 237.4 --a 0.0004 --n 0.37 --density 975 \
  --flow 1.279 --length 0.3302 --iterations 10 --time 5.619

What I learned

  • Turning messy CAD exports into clean, correctly scaled geometry was harder than the physics itself.
  • Computational geometry libraries make otherwise intractable shapes easy to simulate.
  • Packaging a script as an installable CLI tool makes it usable by the rest of a team.

Future work

  • Vary oxidizer flow and specific impulse over the burn instead of holding them constant.
  • Report O/F ratio and flag sliver fuel left at burnout.
  • Validate predictions against static fire test data.
  • Read DXF directly to remove the Inkscape dependency.
